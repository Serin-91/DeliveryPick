# DeliveryPick 개발 회고록

## 오늘 개발하면서 있었던 시행착오

오늘 개발하면서 가장 오래 막혔던 부분은 Environment Variables 설정이었다. 환경변수에 값을 입력하는 과정에서 `Value` 값을 잘못 넣었는데, 처음 다뤄보는 기능이다 보니 어디가 문제인지 바로 알아차리지 못했다. 설정을 마친 줄 알고 다음 단계로 넘어가려고 했는데 계속 진행이 되지 않아서 꽤 답답했다.

결국 원인을 확인해 보니 코드 문제나 서비스 문제라기보다 내가 입력한 값 자체가 잘못된 것이었다. 사소해 보이는 설정 하나 때문에 다음 단계로 아예 나아가지 못했다는 점이 인상 깊었다. 앞으로는 환경변수처럼 한 번 잘못 설정하면 전체 기능에 영향을 주는 부분은 입력 후 바로 다시 확인하는 습관을 들여야겠다고 느꼈다. 처음 보는 설정일수록 그냥 넘어가기보다, 어떤 값이 들어가야 하는지 하나씩 확인하면서 진행해야 할 것 같다.

또 개발 중에 와이파이가 계속 끊기는 현상도 있었다. 정확한 원인은 아직 모르겠지만, 개발 서버 확인이나 자료 검색을 하다가 흐름이 끊기니 집중하기가 어려웠다. 다음에는 이런 문제가 반복되면 와이파이 상태, 다른 기기 연결 여부, 개발 서버 자체 문제인지부터 차례로 확인해 봐야겠다.

## 기획 단계에서 느낀 점

이번 DeliveryPick을 만들면서 기획을 너무 큰 틀만 잡고 개발을 시작했다는 생각이 들었다. 처음에는 일단 기능을 만들면서 필요한 것을 추가하면 된다고 생각했는데, 실제로 해보니 수정하고 추가하고 다시 수정하는 일이 계속 반복됐다. 화면을 만들다가 필요한 데이터가 빠진 것을 발견하고, 기능을 연결하다가 예외 상황을 뒤늦게 생각하는 식이었다.

이 과정이 반복되면서 개발 시간이 늘어나고, 이미 만든 부분을 다시 손보는 일도 많아졌다. 물론 개발하면서 기획이 바뀌는 건 자연스러운 일이라고 생각하지만, 적어도 기본적인 사용자 흐름이나 화면별 기능, 필요한 데이터 정도는 더 구체적으로 정리한 뒤 시작했으면 훨씬 덜 힘들었을 것 같다.

앞으로는 큰 틀을 정한 뒤에 바로 개발하기보다, 큰 틀에서 점점 세부적으로 내려가는 방식으로 기획해 보려고 한다. 예를 들어 화면 하나를 만들기 전에 그 화면의 목적, 보여줄 정보, 사용자가 누를 버튼, 버튼을 눌렀을 때의 동작, 데이터가 없을 때의 화면까지 간단하게라도 적어둘 생각이다.

## 앞으로 개선할 점

- 환경변수나 API 키처럼 중요한 설정은 입력 후 한 번 더 확인하기
- 처음 사용하는 기능은 공식 문서나 예시를 보고 값의 형식을 먼저 이해하기
- 개발 전에 사용자 흐름과 화면별 기능을 간단하게 정리하기
- 필요한 데이터와 예외 상황을 미리 생각해 보기
- 개발 중 문제가 생기면 무작정 여러 방법을 시도하기보다, 원인을 하나씩 분리해서 확인하기

## 마무리

오늘은 작은 설정 실수 하나가 개발 진행 전체를 막을 수 있다는 것을 배웠다. 동시에 기획을 대충 시작하면 나중에 수정 비용이 계속 커진다는 것도 느꼈다. 아직 익숙하지 않은 부분이 많아서 시행착오가 생기지만, 이번 경험을 다음 작업에서 체크리스트처럼 활용하면 같은 문제를 조금씩 줄일 수 있을 것 같다.
